# 机票雷达

本地运行的成人单程机票监控系统。后端需要 Python 3.11+ 和 tzdata 时区数据库；飞猪查询适配器另需 Node.js 18+ 和本地安装的官方 CLI。

## 启动

Windows 首次安装：

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
npm ci --ignore-scripts
./start.ps1
```

本机已安装，可直接运行 `./start.ps1` 或 `.venv/Scripts/python.exe app.py`，打开 http://127.0.0.1:8765 。Linux/macOS 使用 `.venv/bin/python`。通过 `PORT` 环境变量改变端口。关闭进程、休眠或断网时无法持续监控，建议部署在持续开机的个人电脑或服务器上；当前仅监听本机，不适合直接公网暴露。

如果重复启动，程序会识别已运行的机票雷达，提示访问地址并正常退出，不再显示 WinError 10048 堆栈。若其他程序占用了端口，会明确提示冲突，不自动关闭其他程序。全局 Python 缺少 tzdata 时会提示使用项目虚拟环境。

首次复制项目到其他电脑时，先运行 `npm ci --ignore-scripts` 安装锁定版本的飞猪工具。本机已安装 `@fly-ai/flyai-cli@1.0.16`。

## 使用

1. 在“数据与邮件”中添加授权票价接口、SMTP 邮箱并保存。发送测试邮件确认可用。
2. 新建监控，搜索始发和目的城市/机场，选择具体机场或“城市全部机场”，填写出发单日或不超过 31 天的日期区间、含税目标价、邮箱。
3. 默认比较直飞和一次联程转机；可显式允许分开出票的自行中转。自行中转只组合同机场衔接且等待 3–8 小时的航段，联程等待 90 分钟–8 小时。国际自行中转的签证与入境资格仍需用户核实。
4. 无接口时可建立演示监控。演示使用固定模拟数据，永不发送真实提醒。真实监控无数据源时明确显示待配置。

飞猪已通过官方 FlyAI 工具完成真实查询验证。首次启动会添加飞猪（启用）及去哪儿、携程、东航、南航、厦航（待授权、禁用）的来源配置，保留已有配置。其他平台当前只有已核实的官方接入入口，尚无原生查询适配器，不能启用。取得对应权限和协议后才能完成真实接入，不可将平台首页填作统一 JSON 接口。

## 飞猪与平台接入状态

详见 [接入说明](docs/providers.md)。设置页支持单日只读查询测试，不发送邮件。

- 飞猪官方工具支持无 Key 体验查询，结果数量受限；正式 Key 在飞猪控制台申请，填写到设置页后由环境变量传递给子进程，不放入命令行。若未填写则沿用官方 CLI 的环境/本机配置或体验凭据。
- 当前官方返回 `ticketPrice`，公开文档示例是 `adultPrice`；均未明确保证含全部税费。因此单独展示为“费用待确认”，**即使低于目标价也不发邮件**。不擅自再加一次机建燃油以免重复收费。
- 日期区间逐日查询，直飞/转机分别请求。官方 CLI 单次最多返回 10 条，不能保证覆盖全市场最低价。SHA 等代码可能按城市扩展，项目按实际机场代码二次过滤。
- FlyAI 使用全球机场库中的 IANA 时区解析当地时间，支持夏令时；时区缺失、时钟切换歧义的报价不会猜测偏移。转机行程的联程保障不明，展示为待核实，不当作已确认联程。
- 没有正式 Key 时可能限流；失败会在检查记录中显示。官方 CLI 会生成本机设备标识并随请求发送必要的客户端信息。
- 机建燃油完整的统一协议接口仍可正常参与自动邮件提醒。

## 数据接口协议

城市选择在服务端展开为每个机场组合后查询，供应商仍收到具体 IATA 机场代码。查询范围由服务端数据库确定，不信任客户端提供的机场列表。

每个已启用来源每轮收到一个 POST，Authorization 为可选 Bearer token。服务端适配器负责日期展开、分页、获取目标航线联程及中转枢纽单航段，可返回最多 2000 个报价、响应最多 5 MB。请求超时 25 秒；每个来源失败不阻断其他来源，下轮自动重试。报价必须是本轮查询的可售报价。

```json
{"origin":"SHA","destination":"CAN","date_from":"2026-10-10","date_to":"2026-10-12","connections":true,"self_transfer":false,"currency":"CNY","adults":1}
```

响应格式（金钱字段单位元；所有时间必须包含时区）：

```json
{"offers":[{"currency":"CNY","base_fare":300,"mandatory_fees":0,"taxes_included":false,"self_transfer":false,"url":"https://example.com/offer/123","segments":[{"origin":"SHA","destination":"CAN","departure":"2026-10-10T08:00:00+08:00","arrival":"2026-10-10T10:20:00+08:00","flight":"MU1234","carrier":"MU","distance_km":1200,"airport_fee":50,"fuel_fee":60}]}]}
```

上面价格仅演示协议，不代表现行收费。每个报价包含一个或两个航段。两段报价应是可购买的联程；分开出票必须明确 `self_transfer:true`。为自动拼接分开出票方案，接口需同时提供始发地至枢纽及枢纽至目的地的独立单航段报价，含必要的次日航段。

如果供应商确认已含全部税费和所有必付费用，设置 `taxes_included:true` 并提供 `total`，系统不再次加机建燃油。否则要求逐航段提供 `airport_fee`、`fuel_fee`，加上 `base_fare` 和 `mandatory_fees` 得出总价。费用不得省略成 0 来代表未知。可选行李、选座不计入比较；不可选的服务费必须放入必付费用。

缺费用时，只对已知大陆机场使用设置中的航司规则，按出票当天匹配有效期和承运航司，并要求 `distance_km`。800 公里（含）以下使用 `fuel_short`，以上用 `fuel_long`。国际/港澳台或未知机场要求完整含税价或明确的费用。不预置燃油收费，因其会调整；过期、重叠规则或缺里程将拒绝该报价参与提醒。规则由管理员根据航司公告维护，系统不会自动抓取公告。

## 提醒规则与持久化

- 仅最低有效报价 **严格低于** 目标价时发信；目标价相等不触发。
- 同一监控同一行程同来源成功提醒后，只有再降价且距上次发送至少 1 小时才提醒。
- 邮件失败不写成功记录，下次检查重试。SMTP 仅允许 SSL/TLS 或 STARTTLS。
- SMTP 在远端已接收但本机尚未写入记录时发生崩溃，可能重复提醒，属于至少一次投递。
- SQLite 持久保存监控、最低价历史及事件；重启后恢复调度。过去的日期不再调度。
- `data/config.json` 存储本地接口密钥和 SMTP 授权码，不经读取接口回传。配置文件应只对本人可读；数据目录已被 git 忽略。更换来源地址时不会继承旧密钥。
- 本地接口校验 Host/Origin，无跨域许可；仅绑定 127.0.0.1。当前设计是个人单进程应用。

涵盖费用累加、避免重复加税、缺费拒绝、转机衔接、分开出票选项、邮件去重与失败重试、演示隔离、严格阈值、日期验证。

收费说明参考：[东航旗下上航国内航线燃油调整公告](https://global.ceair.com/global/static/Announcement/AnnouncementMessage/notices/202604/t20260403_29751.html)。该公告说明按销售日期和航段距离调整收费，不用其历史数值作为系统当前默认值。

## 全球机场与逐航班比价

- 随项目分发 airportsdata MIT 数据快照：28,298 条机场记录，234 个国家和地区，7,884 个带 IATA 代码的机场。首次启动自动建立独立 SQLite 数据库 `data/airports.db`，可离线重建。详情与许可证见 [数据说明](resources/README.md)。
- 支持英文城市、常用中文机场名、IATA/ICAO 搜索。无 IATA 的机场只用于资料浏览。机场数据量不代表票价来源的覆盖量。
- `SHA` 是具体虹桥机场，`CITY:SHA` 是上海全部机场；同理 `CITY:BJS`、`CITY:CTU`、`CITY:LON` 等。选择器明确展示名单；服务端拒绝出发和目的范围重叠。旧监控仍按原具体机场运行。
- “航班比价”无需邮箱，也不触发提醒。异步查询结果保留在当前进程内最多 1 小时，最多 30 项、同时 2 项；重启后清空。监控中的“逐航班比价”则读取已持久化的最近一次检查。
- 按实际机场对、出发日期时间、展示航班号聚合不同来源的本轮最低价，保留代码共享航班的独立航班号，不把不同日期或机场合并。含税最低价和口径未确认展示价分开计算；“最低”指本轮收到的报价，不是历史最低或全市场保证。
- 列表显示航司、航班号、机场、当地起降时间、UTC 偏移、最低含税价/展示价，支持航司筛选、航班号/机场搜索、价格/时间排序、每页 20 行。已取消旧的前 30 个报价截断。
- 单次机场组合 × 天数 × 直飞/转机搜索次数最多 120，超出会要求缩小范围，不会偷偷忽略机场。飞猪每次只返回有限结果，不能保证每班都在接口返回范围内；界面会保留数据来源的覆盖提示与错误。


## 公开网站数据源（2026-09 接入）

启动后自动追加同程和春秋来源，保留已有接口、密钥和开关。同程默认启用；春秋日历初次查询成功，但复测返回非 JSON 页面，作为试验来源默认停用，可在设置中手动测试。需本机安装 Node.js 和 Microsoft Edge，在项目目录执行 `npm ci --ignore-scripts` 安装 Playwright。无需登录或填写这两家的 API Key。

| 来源 | 本轮可提供的数据 | 使用范围 |
| --- | --- | --- |
| 同程旅行 | 公开航班页中的直飞航班号、航司、实际机场、起降时间、最低展示价 | 加入逐航班列表，与飞猪同一航班合并展示各来源报价 |
| 春秋航空（试验，默认停用） | 成功查询时提供官网当前及次月日历的日期和航线起价 | 出现在查询结果的平台提示中；无航班号，不能据此预订具体航班 |

这些公开报价尚未确认完整税费，因此不会作为含税总价或触发邮件。春秋价格只代表城市航线参考，不能保证具体机场匹配。转机仍使用已有飞猪或统一协议接口，同程抓取暂不包含经停和转机。携程公开搜索页的 robots 规则禁止抓取且访问受限，其余合作来源仍需授权，未将它们伪装为可用来源。

采集器读取正常页面和浏览器加载的数据，不登录、不下单、不绕过验证码或访问限制。每站至少间隔 120 秒（网站规则更长则从其规则），成功结果缓存 15 分钟；过期报价不作为本轮结果。robots 核验失败时停止采集。缓存和限速状态保存在 `data/crawler-cache.db`，重启保留。

大日期区间、多机场组合可能只返回部分页面：界面显示覆盖数量及失败原因。监控后续轮次优先尝试尚未抓取或最久未更新的页面；建议缩小范围以获得更新鲜、完整的结果。程序不会等待限速时间阻塞整个监控，也不会承诺覆盖全市场。浏览器查询单页最多约 65 秒，页面变化或访问限制会显示失败状态。
